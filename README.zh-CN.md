# NOVA Desktop

简体中文 · [English](README.md)

NOVA Desktop 是一个使用纯 C 和原生 Win32 API 编写的轻量 Windows 工作区启动器
与多窗格文件管理器。普通工作区可保存应用、快捷方式、文件和文件夹；固定的
**“目录”**工作区用于日常文件管理。

项目不依赖 Web 运行时、安装程序或后台服务，也不需要安装 Q-Dir。

## 功能亮点

- **原生设备同步**：在“设置 → 设备与同步”登记两台电脑、配置最多 16 个目录配对，
  管理增量传输与断点续传。服务器暂存缺失块，接收确认后回收；本机无需 Python 或
  独立 Web 服务。配置、迁移与限制见 [同步说明](sync/README.md)。
- **12 种可调文件管理布局**：四窗格、双栏、双行、单窗格、四种三窗格组合，以及
  三列、三行、四列、四行。拖动窗格边界即可调整大小，比例会保存在本地并恢复。
- **独立标签与历史**：每个窗格最多 12 个清晰高亮的标签，各自保存路径和
  前进/后退历史。按住目录标签后拖动，即可调整并保存该窗格的标签顺序。
- **原生 Windows 文件操作**：多选、排序、筛选、右键菜单、缩略图、剪贴板、
  拖放、重命名、删除和新建文件夹均沿用 Windows Shell 行为；每个窗格都直接
  提供剪切、粘贴、删除和新建文件夹按钮。
- **按目录执行命令预设**：可从窗格工具栏执行默认命令、在下拉菜单中选择其他
  已保存命令，或管理最多 16 条命名预设。工作目录始终是当前活动窗格的文件系统目录。
- **工作区启动器**：最多 8 个工作区、每区 20 项；支持长按拖动排序或跨区移动、
  搜索、一次性启动整个工作区，或把侧边栏折叠成紧凑导航轨。
- **多条批量任务**：在**设置 → 批量任务**中保存最多 16 条命名任务，每条包含
  最多 24 个可独立编辑工作目录和命令的子任务，并支持顺序/同时执行。
- **JSON 配置**：工作区、启动项、任务、命令、标签、布局、目录树开关、收藏和
  界面偏好统一保存在 `config/nova.json`，可以纳入 Git 版本管理。
- **多种窗口形态**：普通窗口、置顶、桌面围栏、托盘，以及可选的开机启动。
- **简体中文与英文界面**：在**设置 → 语言**中即时切换，下次启动自动恢复。

## 系统与构建要求

- Windows 7 或更高版本
- 从源码构建需要 MinGW-w64 GCC 和 `windres`
- SSH 构建还需要同一 MinGW 工具链的 OpenSSL 3 开发头文件与静态 `libcrypto.a`
  （MSYS2 MINGW64：`pacman -S mingw-w64-x86_64-openssl`）；最终程序不依赖 OpenSSL DLL。
- 构建与测试脚本需要 PowerShell
- 增量同步需要同一工具链的 zlib 头文件与静态 `libz.a`
  （MSYS2 MINGW64：`mingw-w64-x86_64-zlib`），运行时不依赖 zlib DLL。

项目已在 `third_party/sqlite` 中固定 SQLite 3.53.4 并静态链接。首次构建完成后
无需联网。SQLite 用作内存事务、JSON 解析和旧数据库迁移；新配置以 JSON 保存。

脚本会在选中编译器的前缀下查找 `include/openssl` 和 `lib/libcrypto.a`，
也支持部分 MinGW 包使用的 `opt` 子目录。独立安装的兼容 MinGW OpenSSL 可用
`$env:NOVA_OPENSSL_ROOT` 指向包含 `include`、`lib` 的前缀目录。
构建、测试只修改自身进程的搜索路径。部署会在暂存、推送之前编译并链接一个
OpenSSL 探针；缺少头文件、静态库或库不兼容时，会先停止部署。
旧版 OpenSSL 会被拒绝，以保留已声明的 Ed25519 支持并与随包许可证一致。
也支持本机的 `build/deps/openssl` 前缀，条件是其 `compiler.txt` 包含选中
`gcc.exe` 的完整路径；构建依赖被 Git 忽略，需要在每台电脑分别准备。

## 构建与运行

构建、部署和测试脚本按顺序使用 `NOVA_MINGW_BIN`（如已设置）、`PATH`，
再自动查找常见 MSYS2 安装中的 `mingw64/bin` 或 `ucrt64/bin`。
自动查找范围为本地磁盘根目录及下一级目录，以及 Local AppData。
其他安装位置可手动指定：

```powershell
$env:NOVA_MINGW_BIN = 'C:\msys64\mingw64\bin'
```

所选目录必须同时包含 `gcc.exe` 和 `windres.exe`。脚本只调整自身进程环境，
不会修改系统或用户的 PATH。

```powershell
.\deployment\build.bat
.\build\nova-desktop.exe
```

构建和测试入口统一位于 `deployment/`。批处理脚本根据自身位置定位仓库，
也可以从其他工作目录调用。构建脚本支持可选输出路径（相对于仓库，或绝对路径），
方便在正式 exe 被运行中的程序占用时编译预览版：

```powershell
.\deployment\build.bat "build\nova-desktop-preview.exe"
.\deployment\test.bat --interactions
.\deployment\test-storage.bat
.\deployment\test-files.bat
```

每次成功编译还会更新 `build/packages/nova-desktop.exe` 和
`build/packages/config/nova.json`。固定 exe 覆盖之前的副本，编译失败时保留旧副本。
如果正在运行这份 exe，建议先关闭再编译。若 Windows 允许在运行中替换，
被占用的旧 exe 备份会保留，后续构建重试清理，不会因此中断编译或 ZIP 打包。
真正无法替换 exe 时，构建仍会停止。

按顺序提交、推送、编译并打包本地便携版：

```powershell
.\deployment\deploy_local.bat "feat: 描述本次改动"
```

提交说明可省略，默认包含时间戳。脚本会暂存**所有未被忽略的改动**，有变化时提交，
将当前分支推送到配置的上游（未配置时使用 `origin` 同名分支），然后将 exe 和 ZIP
生成到 `build/packages/`。每次打包使用独立目录，包含源码提交号、两份 README、
许可证、两份 NOTICE 及 `config/nova.json` 配置副本。二进制仅保存在本地并被 Git 忽略，不会发布 Release。
任一步失败都会停止；推送后若编译失败，远程源码提交仍保留，重新运行即可重试构建，
不会创建空提交。脚本不会关闭正在运行的 NOVA。部署前请先运行相关测试。

跨电脑同步使用数据时，先关闭源电脑的 NOVA，保存待处理的任务和会话修改，
再在源电脑部署，将更新后的 `config/nova.json` 提交并推送。目标电脑需要在
`git pull --ff-only` **之前**关闭 NOVA，再运行 `deployment/build.bat` 并启动新程序。
部署脚本提交、推送当前仓库，不会拉取远程更新。部署和编译输出会显示 JSON 路径、
初始化状态、任务数量、各窗格标签数及 SHA256，压缩包的 `revision.txt` 也记录配置校验值。
“没有改动”的部署无法取得另一台电脑尚未提交的配置。保存的是目录路径，实际文件
和文件夹需要在目标电脑存在。

也可在仓库根目录运行 `mingw32-make -f deployment/Makefile`，它调用同一构建脚本。

直接打开文件管理页面：

```powershell
.\build\nova-desktop.exe --files
```

在仓库内运行程序时，配置直接读写：

```text
config\nova.json
```

在仓库外运行发布包时，读写 exe 旁边的 `config/nova.json`。
JSON 文件不存在，或提供空的 `initialized: false` 初始配置时，首次启动会导入
`%APPDATA%\NOVA Desktop\nova.sqlite`，或旧版 `config.ini`、`file-manager.ini`；
原文件及其备份保留。没有旧数据时生成默认配置，此后只使用 JSON。
迁移保留所有路径、名称、命令和稳定 ID。

JSON 使用 UTF-8 和版本号，64 位 ID 保存为十进制字符串。保存使用原子替换，
无效、重复、超容量或更新版本的数据会拒绝加载，避免覆盖原文件。
启动时更新 `config/nova.backup.json`；手动编辑或恢复 JSON 前请关闭 NOVA。
主配置不会被 Git 忽略，备份和临时文件仍忽略。
频繁变化的状态另外保存在被 Git 忽略的 `config/local.json`：活动工作区、当前选中
标签、窗口模式、侧边栏状态、窗格布局、目录树开关和分隔线位置。任务、启动项、
命令预设、已保存标签目录、收藏和语言继续保存在共享的 `nova.json`。
旧的合并配置首次启动时自动拆分，本机状态优先。启动分别备份两份文件。
配置包含用户路径与命令，提交或
部署时请查看其 Git 差异。详见[配置格式](config/README.md)。

同一文件也保存实际使用数据：任务及子任务目录/命令、工作区启动项和任务入口、
命令预设、目录标签和收藏。使用程序时会直接保存这些数据，并非只保存配置模板。
如需在打开界面前迁移现有数据，关闭 NOVA 后运行
`build/packages/nova-desktop.exe --migrate-data`。此模式只迁移、保存数据并更新备份，
不会执行任务或打开启动项。

## 使用工作区

- 将文件、文件夹、程序或快捷方式拖入普通工作区，或点击**添加文件** /
  **添加文件夹**。NOVA 只记录路径，不会移动或复制原项目。
- 双击项目或按 Enter 交给 Windows 打开。从 NOVA 移除启动项不会删除原文件。
- 点击 `+` 新建工作区；重命名和删除位于**设置**菜单。固定的“目录”工作区不能
  重命名或删除。
- 点击 NOVA 标识旁的箭头，或按 `Ctrl+B`，可折叠或展开工作区侧边栏。紧凑导航轨
  仍可切换工作区，所选状态会在下次启动时恢复。
- 按 `Ctrl+K` 搜索当前工作区。需要排序或跨区移动时请先清空搜索；直接拖动图标
  到另一个图标可调整区内顺序，拖到另一个普通工作区可跨区移动。指针正常移动超过
  Windows 拖动阈值后会立即开始拖动，原地按住 350 毫秒也能开始。这只会移动 NOVA
  中的启动项，原文件位置不变；固定的“目录”工作区不接收启动项。
- 点击**全部启动**或双击工作区名称，可对当前快照中的每个项目各执行一次打开。
  程序没有循环执行或后台定时启动队列。

## 文件管理快捷键

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl+L` | 聚焦目录/命令地址栏 |
| `Alt+Left` / `Alt+Right` | 后退 / 前进 |
| `Alt+Up` | 上级目录 |
| `Ctrl+T` / `Ctrl+W` | 新建 / 关闭标签 |
| `Ctrl+Tab` | 下一个标签 |
| `F6` | 下一个窗格 |
| `F5` | 刷新 |
| `Ctrl+C/X/V` | 在原生文件视图中复制 / 剪切 / 粘贴 |
| `F2` / `Delete` | 重命名 / 删除 |
| `Ctrl+Shift+N` | 新建文件夹 |

如果文件列表缩在左上角、显示不完整，刷新也会重新同步原生文件视图与窗格尺寸。

地址栏支持普通路径、相对路径、UNC 网络路径、`shell:` 地址和
`%USERPROFILE%` 等环境变量。输入 `git status` 一类普通命令会以当前窗格的
文件系统目录作为工作目录启动 `cmd.exe`；使用 `>` 前缀可强制按命令执行。

每个窗格在文件操作按钮之后还有一个命令分裂按钮。单击主体可执行默认预设；单击
箭头可执行其他预设、选择默认命令或打开“管理命令…”。预设名称和命令保存在本地
JSON 配置中。NOVA 初始提供 `cmd.exe` 预设（`cd .`），可在当前目录打开命令提示符，
不会修改目录内容。

## SSH 服务器

每个文件窗格的标签栏旁都有**本地 / 服务器**模式按钮，四个窗格可以独立设置。
切到**服务器模式**后，点击 `+` 或按 `Ctrl+T` 直接列出已保存的服务器；选中后填写
该服务器的登录凭据，在新标签连接。还没有服务器时会打开服务器管理，列表中也可
选择“管理服务器…”。取消选择不创建标签。切换模式保留现有标签和连接；本地模式
的新标签从此窗格已有的本地目录打开。模式只保存到本机 `config/local.json`，恢复时不自动连接。

文件管理器工具栏的**服务器**按钮用于保存名称、主机、端口、用户名和远程初始
绝对目录，并在当前窗格新开远程标签。支持密码或私钥认证，包括加密的 OpenSSH
Ed25519 私钥。点击**保存**或**连接**会把私钥路径和密码/口令保存到当前 Windows
用户的本机凭据管理器。重新打开或切换服务器时自动回填，密码保持掩码显示。
NOVA 记住私钥路径，不复制私钥内容，原私钥文件应保留在原位置。
修改主机、端口或用户名会清空回填的登录字段；**清除登录信息**、移除服务器，或将
私钥和密码字段都清空后保存，会删除该服务器的本机登录信息。
凭据不会随 Git 或便携包迁移，换电脑或 Windows 用户后需重新填写一次。
凭据保存失败会明确报错，配置写入失败会恢复原登录信息。密码、口令、私钥路径均
不写入 JSON。首次连接必须独立核验 SHA256
主机指纹；信任记录按主机和端口存入当前用户的 Windows 凭据管理器，指纹变化时阻止连接。
服务器保存公钥，本机应选择与之匹配的私钥，例如 `id_ed25519`，而不是 `id_ed25519.pub`。
连接前会检查是否提供密码或私钥；首版不会自动使用 SSH Agent 或其他 SSH 软件的凭据。
选成公钥、PPK 或 UTF-16 文件时会明确提示；私钥文件不会被修改。
连接失败会弹出完整错误，并在终端视图保留可复制的阶段、系统/SSH/SFTP 错误码和说明。

服务器需要允许该账号使用 SSH exec、SFTP 子系统及 POSIX `sh`，无需安装 NOVA、
代理或额外监听端口；首版面向 Linux/POSIX。最多保存 16 条连接配置，最多同时使用
4 个远程标签的网络线程，断开或关闭标签释放连接。恢复标签不会自动连接。连接信息
及远程标签路径保存在共享 `nova.json`，提交前请检查主机、用户名和目录。
移除连接配置不会删除服务器文件。

远程标签沿用布局、历史、收藏、刷新和上级目录，路径区分大小写。输入绝对/相对目录
进行导航；`> 命令` 强制在远程终端执行，带空格的普通命令也会远程执行。
单个词按相对目录处理，带空格的相对路径可加 `./` 前缀；已列出的目录名也优先导航。
文件夹模式的内容区域用于显示文件列表。远程命令按钮打开**终端**；在地址栏提交的
命令也会切换到终端并在其中的 Shell 执行，单词命令可输入 `> pwd`。
首次启动终端时仅暂存这次明确提交的命令；启动失败或断开会丢弃它，命令不会自动重试。
**断开不保证远端进程退出**，远程操作的结果可能未知。

点击远程标签内的**终端**，或按 `Ctrl+Shift+T`，可将文件列表切换为 SSH 交互终端。
终端从文件视图当前显示的目录启动服务器上的 Shell；服务器需允许 PTY 分配并提供
`stty`。切回**文件夹**或切换标签后，同一 Shell 继续保留 `cd`、环境变量和命令历史。
启动后，文件视图和终端各自维护目录，不会因切换视图而重置 Shell。
支持 ANSI 彩色输出、UTF-8、Tab 补全、方向键、Ctrl+C 和全屏程序的备用屏幕。
终端获得焦点时，快捷键发送到服务器；通过视图按钮或 `Ctrl+Shift+T` 返回文件操作。
拖动选择文本，`Ctrl+Shift+C` 复制选区（未选择时复制可见屏幕），
`Ctrl+Shift+V` / `Shift+Insert` 粘贴最多 8192 字符。鼠标滚轮或滚动条可查看最近
1000 行历史。缩放窗口会同步远端 PTY 尺寸。关闭、断开、退出 Shell 或切换界面语言
会结束会话，可点击**连接**重新打开。终端内容和会话不写入配置，重启不会重放命令。
终端使用静态链接的 libvterm，不启动本地终端进程。

远程列表支持单项选择、右键菜单、`Ctrl+C/X/V`、`F2`、`Delete`、`Ctrl+Shift+N`。
同服务器复制普通文件，或移动文件和目录；上传/下载按钮递归传输文件和目录并显示
当前文件进度，双击普通文件进入下载选择。首版传输/重命名**拒绝已有目标**，不合并
目录；目录复制可先下载再上传。本地与远程传输使用上传/下载，暂不接入系统剪贴板、
拖放和跨服务器复制。下载拒绝不安全的 Windows 文件名，递归传输不跟随符号链接或
重解析点。远程删除需确认永久删除，不进入 Windows 回收站，也不跟随符号链接。
失败可能已完成部分项目，应刷新核实。目录最多 10000 项，递归最多 32 层/10000 项，
超限报错，不用截断列表替换视图。网络等待通常为 30 秒，交互终端无空闲超时；
DNS 解析和取消延迟还受 Windows 网络栈影响。
远程路径最多 2007 个 UTF-16 代码单元；本地传输及私钥路径最多 259 个字符。

## 批量任务

打开**设置 → 批量任务…**，左侧任务库集中放置**新建任务**和**删除任务**，
右上角为**保存任务**。填写名称、默认命令和执行模式后，点击**新增子任务**选择工作目录。
新增子任务会复制默认命令，之后可独立修改。选中子任务，点击**编辑**或双击，
在下方修改工作目录和命令，再点击**应用修改**；**删除**仅移除该子任务的配置。
同一任务的工作目录不能重复；没有独立命令的旧子任务继续继承默认命令。
在子任务上按住鼠标左键 350 毫秒后，即可上下拖动排序。插入线标示新位置，
拖到列表边缘会自动滚动；松开鼠标保存顺序，按 Esc 或在列表外松开则取消。
目录、命令和执行结果一起移动，顺序执行遵循保存后的排列。任何子任务执行期间暂时禁用排序。
子任务列表上方的**执行选中项**只运行选中的一行，并先保存待处理的修改。
执行状态和捕获的输出显示在对应行，双击已完成项可查看输出（包含成功的命令）。
其他行保留原有结果。单独执行期间，可以执行、编辑或删除其他空闲子任务，也可以新增子任务。
单独执行的子任务立即独立启动，任务设置为顺序执行时也无需等待其他行结束；
正在运行的行不能编辑、删除或重复启动。任务名称、默认命令、执行模式和任务切换
在所有活动子任务结束前保持锁定。选中单独启动的运行项，点击**取消选中项**，
只终止该命令及其子进程，其他子任务和排队任务继续执行。该行显示**正在取消…**，
结束后可重新编辑或执行。**取消全部**会终止所有活动命令并清空排队任务。
整组任务执行期间仍锁定编辑和单独执行操作。
从左侧选择已保存的任务，点击**一键执行**即可。保存、切换子任务或任务、执行以及
关闭窗口时也会保存待处理的修改；无效输入需要先修正。每条任务独立记住执行模式：

- **顺序执行**：等一个目录执行结束后，再执行下一个目录。
- **同时执行**：为所有目录发起执行，无需等待前一个结束。

每次运行一条已保存任务，同时执行模式最多运行 24 个目录命令。
**取消全部**会终止正在运行的命令及其子进程，并跳过尚未开始的目录。
某个目录失败会显示退出码和命令的末尾输出；双击失败项可查看完整的已捕获详情，
其他目录仍继续处理。命令的标准输入关闭，交互式提示会直接失败而不会在后台无限等待。

在任务管理窗口点击**添加到工作区…**，选择普通工作区，即可创建任务快捷入口。
支持双击、Enter，以及工作区的**全部启动**。同时触发多条任务时，各任务配置
会形成快照并依次入队，任务内部仍按其顺序/同时模式执行。已运行或排队的任务
不会因重复点击再次入队；**取消全部**也会清空尚未开始的任务队列。

快捷入口通过固定 ID 引用任务，改名或调整列表顺序后仍对应同一条任务。
移除快捷入口不会删除任务；删除任务后，旧入口显示失效，不会启动其他任务。
固定“目录”工作区不支持添加任务快捷入口。

命令使用 Windows cmd 语法，最多 2047 个字符，例如 `git pull origin main`、
`npm run build`、`git status && git log -1`。原有单条配置会迁移为第一条任务；
已有任务集合通过事务升级，保留原任务 ID 和命令。
任务保存在 JSON 配置中；目录作为工作目录单独传给系统 `cmd.exe /d /s /c`。

标题栏从左到右依次为**设置**、桌面围栏、置顶和标准窗口按钮。点击最大化/还原按钮
从最大化还原时，窗口会回到当前显示器工作区中央的适中尺寸（最多 1100 × 760 逻辑像素）。

## 当前限制

- 启动器工作区与批量任务中的路径目前最多 259 个字符。文件管理地址栏最多
  2047 个字符，实际访问仍受 Windows Shell 行为限制。
- 本项目独立实现了类似 Q-Dir 的核心多窗格工作流，并非一比一复刻；不支持导入
  `.qdr` 会话，也未覆盖 Q-Dir 的所有选项。
- Windows Shell 扩展、网络设备或缩略图提供程序可能使文件视图等待。隐藏视图会在
  闲置后释放，但 Windows 和第三方缓存不受 NOVA 的内存策略控制。

## 配置合并冲突

在 `main` 分支日常更新时，先关闭 NOVA，再运行 `deployment/sync_config.bat`。
它拉取 `origin/main`，将公共祖先、本机及远端 JSON 备份到被忽略的
`build/config-sync/`，随后快进更新并合并未提交配置。独立增删可自动合并；
启动项重新编号及已关闭标签残留字段不算编辑。真正的双方修改冲突会在改变
工作文件前停止。`-Preview` 只获取远端并生成带备份的预览。命令不提交、推送，
也不操作已有 stash；发布前核对并提交保留下来的本机修改。已暂存的配置、未完成的
Git 操作或分叉提交需要另行处理。任务、保存目录等共享数据的修改仍会阻塞普通
`git pull`；本机状态拆分只能避免临时界面状态造成这种阻塞。

如果拉取被未提交的 `config/nova.json` 阻止，先关闭 NOVA，再运行
`git stash push -m "nova config before pull" -- config/nova.json` 保留本机修改。
源电脑发布更新后拉取，再用 `git stash apply 'stash@{0}'` 恢复修改并保留 stash。
恢复出现冲突时，按下方语义合并流程处理后再编译、启动；验证合并数据前保留 stash。
直接执行 `deployment/configuration_info.ps1` 现在会显示诊断，点加载仅导入函数。

先关闭 NOVA，运行 `deployment/resolve_config.bat`，会备份 Git 的公共祖先、本机、
远端三份数据，并在被忽略的 `build/config-merge/` 下生成合并预览。
`deployment/resolve_config.bat -Apply` 应用无冲突结果并暂存，之后提交合并再推送。
两台电脑即使都新增为 Task1，也会按稳定 ID 保留双方新增任务及任务入口。
同一任务被同时编辑、删除与编辑冲突或超容量时需要人工确认，不强行选一边或截断数据。
运行状态 `local.json` 不参与同步。

## 原生设备同步

从“设置 → 设备与同步”（或 `--sync`）登记 A/B、配对目录并管理传输。新建与迁移的
目录默认暂停；第二台电脑选择已有同步组，再指定自己的本机路径。云端确认回收后，
本机块缓存仍需保留，目前不自动清理历史块。
[配置、迁移与限制](sync/README.md) 包括错峰交接、删除策略与配额说明。
`deployment/test-sync.bat` 验证配置和原生界面；可选回环测试验证实际 SSH 协议、
增量复用与断线恢复，不接触真实工作目录。

原生管理窗口新增“服务器”页，可从 EXE 内置资源一键部署、检查连接、迁移续传，
并在切换提交前恢复旧端。新电脑只需通过界面填写自己的 SSH 登录信息、登记设备并
配对目录，无需手动脚本或本机 Python。服务器需为支持 SSH/SFTP 的 Linux，预装
Python 3.9+ 与 SQLite JSON，并允许写入所选目录。迁移保留身份、队列和历史，冻结
旧端并向离线设备提示新目标，流程与边界见 [同步说明](sync/README.md)。
